# dotfiles

Personal dotfiles, managed with [chezmoi](https://www.chezmoi.io/).

Currently tracks the Neovim configuration (`~/.config/nvim`). Anything else you
want managed gets added the same way — see [Adding a new dotfile](#adding-a-new-dotfile).

## How chezmoi works

chezmoi keeps a **source directory** — this repo, checked out at
`~/.local/share/chezmoi` — holding the canonical copy of every tracked file, and
*applies* that state out to your home directory.

The mapping is by filename convention. A leading `dot_` becomes a literal dot:

```
dot_config/nvim/init.lua        ->        ~/.config/nvim/init.lua
```

So the source directory is a mirror of `$HOME`, containing only the files you
have chosen to track.

The important consequence: **the repo is the source of truth**. Editing
`~/.config/nvim/init.lua` directly changes your live config but not the repo;
you have to either edit the source copy or pull the change back in with
`chezmoi add`. See [Day-to-day](#day-to-day) below for both directions.

## Day-to-day

```bash
chezmoi edit ~/.config/nvim/init.lua   # edit the source copy, then apply it
chezmoi diff                           # preview what applying would change
chezmoi apply                          # write source state out to $HOME
chezmoi status                         # short summary of pending changes
```

If you edited a file in `$HOME` directly and want to keep the change:

```bash
chezmoi add ~/.config/nvim/init.lua    # pull it back into the repo
chezmoi re-add                         # or: pull back every tracked file at once
```

To commit and push:

```bash
chezmoi cd                             # opens a shell in the source directory
git add -A && git commit -m "..." && git push
exit
```

## Setting up a new machine

```bash
# install chezmoi, then:
chezmoi init --apply git@github.com:brucepucci/dotfiles.git
```

`init --apply` clones this repo and applies it in one step. The scripts described
below then install the external dependencies and all Neovim plugins, so a fresh
machine ends up with a working editor without further steps.

Neovim itself is not installed by the scripts — install it first
(`brew install neovim`).

## What's in here

| Path | Purpose |
|---|---|
| `dot_config/nvim/` | The Neovim configuration, applied to `~/.config/nvim` |
| `.chezmoiignore` | Paths chezmoi leaves alone entirely |
| `run_onchange_before_00-install-packages.sh.tmpl` | Installs ripgrep, node, ipython, tree-sitter-cli |
| `run_onchange_after_10-nvim-sync-plugins.sh.tmpl` | Runs `:PackerSync`, installs LSP servers and treesitter parsers |
| `.github/workflows/` | Repo CI; not applied to `$HOME` |

Files and directories beginning with a dot are private to chezmoi and are never
applied to your home directory, which is why `.github/` can live at the root
safely.

### The scripts

Scripts named `run_onchange_*` re-run whenever their *rendered contents* change.
The plugin-sync script embeds a hash of `plugins-setup.lua` and
`treesitter.lua` in a comment, so:

> add a plugin to `plugins-setup.lua` → `chezmoi apply` → the hash changes → the
> script re-runs → `:PackerSync` installs it.

The same trick drives package installation: the package list lives in a comment
in the install script, so adding a package to it causes the script to re-run.

`before_`/`after_` control ordering relative to applying the files themselves,
and the numeric prefixes order the scripts among each other.

### `.chezmoiignore`

`~/.config/nvim/plugin/packer_compiled.lua` is regenerated by packer on every
`:PackerSync`, so it is ignored rather than tracked — otherwise it would show up
as a spurious diff constantly.

## Adding a new dotfile

```bash
chezmoi add ~/.gitconfig
chezmoi cd && git add -A && git commit -m "track gitconfig" && git push
```

For files that differ per machine (or contain secrets), chezmoi supports
templating and encryption — see
[templating](https://www.chezmoi.io/user-guide/templating/) and
[password managers](https://www.chezmoi.io/user-guide/password-managers/).
